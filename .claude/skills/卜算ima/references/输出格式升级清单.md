# 输出格式升级清单（八字 → 各术法可复用）

> 2026-10 从八字输出格式升级中沉淀的**可复用经验**。升级任何术法（紫微/七政四余/六爻/梅花/奇门…）都照这七条走，避免重蹈「没照做格式」的覆辙。
> 每条的**产物示例**见八字：`docs/OUTPUT-EXAMPLE.md`、`search`、`libs/bazi_evaluator.py`、`libs/bazi_json.py`。

## 七条经验

1. **骨架先行 + 黄金样例**（根治「没照做」）
   - 根因：格式规范是散文，机器读后「凭理解重组」必漏项。
   - 做法：每术一份 `docs/XX-OUTPUT-EXAMPLE.md` 逐字合规范例 + 输出骨架模板（②排盘结果〔盘面事实〕③断语〔规则推演〕④结论〔现实建议〕），机器照填不靠理解。

2. **单一真相源**（标签用词与 review.py 逐字一致）
   - 根因：总纲与分术文档标签冲突（如八字 `[白话]` vs 白话层「术语解读/问事解读」）。
   - 做法：三层分离只用「盘面事实/规则推演/现实建议」、白话层只用「术语解读/问事解读」，与 `review.py` 匹配串逐字一致，分术文档不许自造标签。

3. **出处书名引用**（引经可复核；ima 版无行号）
   - 做法：每条 `[原文]` 附出处书名，`search` 检索原文复核，杜绝编造经文。

4. **独立评估者**（对抗性第二意见，非 self-eval）
   - 做法：主判之外用独立规则链从原始数据重推核心结论比对，冲突即标「信号冲突/边界差异」并降级。八字有 `bazi_evaluator`，紫微有 `ziwei_crosscheck`（排盘 parity）。

5. **结构化双轨 --json**（机读可校验）
   - 做法：盘面事实层出 JSON（`schema=XX-panfact-v1`），与散文并存，程序化校验/渲染用。

6. **一眼摘要卡**（借网上「看得懂」层，不牺牲严谨）
   - 做法：开头给一张 3 秒看懂的卡（日主/命宫/五行统计/四化/大运地势吉凶/喜忌），长文是它的展开。**只借「包装好看」，不借「宿命式硬断、无出处黑盒」**。

7. **诚实边界 + 判断停在哪**（不硬断、不投票）
   - 做法：结尾写「判断停在哪」——明确哪些条件成立、哪些有分歧、停在哪一步；无信号组（精确年份+具体生平）不硬猜；几本书相反时并列呈现不按条数投票。
