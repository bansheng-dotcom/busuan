# 取象优化升级（射覆 / 来意 / 测物）

> 状态：执行中
> 建立：2026-10-11
> 范围：金口诀、大六壬、梅花易数 的射覆、来意、测物取象
> 关联：`references/射覆特征画像.md`、`references/金口诀射覆门速查.md`、`libs/shefu_portrait.py`、`libs/rules.py`、`data/类象库.json`

## 一、问题

射覆 / 测物 / 来意等功能「取象不全」——盘里有多个象源（四位、四课三传、三卦体用、神煞、旺衰、数目、所在），但输出只抓到少部分，导致特征画像单薄、来意判断缺失。

## 二、根因（5 条）

1. **类象库覆盖面窄（结构性短板）**：`data/类象库.json` 只有 `天将(12)` + `八卦(8)` 两个节点、每个 6 物性维度。缺——十二地支类象（大六壬/金口诀共用）、梅花《万物类象》的天时/地理/人物/人事/身体/动物/静物/五色/五味/数目等 10 维、金口诀射覆歌总诀(其三)/形状诀(其四)/射物所在/占来意歌。
2. **单象输出、无多象合成**：`rules.jinkoujue_shefu_*` 是单象返回；金口诀四位、大六壬四课三传、梅花三卦没汇入 `shefu_portrait.portrait()` 聚合层。
3. **降分辨率设计主动牺牲完整性**：射覆画像刻意只出 6 维物性、不押物名（为降「猜具体物翻车」风险），这是正确取舍，但代价是取象不全。
4. **来意判断空白**：金口诀「占来意歌」、大六壬初传课体、梅花体用动爻，均未结构化为规则函数。
5. **无「语境→维度选择」与「当代映射」机制**：类象是静态古代类象表，没按问事语境选维度，当代映射（乾=互联网/领导、离=屏幕、AI=乾+坤+离）没接进选择逻辑。

## 四、优化方案（分阶段）

### P0 —— 扩充类象库维度（治本第一步）
- **目标**：类象库覆盖「十二地支」节点 + 八卦补 人物/动物/静物/方位/数目 维度 + 金口诀射覆歌全 4 首结构化。
- **文件**：`data/类象库.json`、`scripts/libs/rules.py`、`scripts/libs/shefu_portrait.py`。
- **验收**：① 新增 `地支` 节点（12 支 × 物类/颜色/数目/方位）；② 八卦每卦 ≥ 8 维；③ 回归测试锁覆盖数。

### P1 —— 多象合成聚合层
- **目标**：金口诀四位、大六壬四课三传、梅花三卦（本/互/变）多象源汇入 `portrait()` 加权聚合。
- **文件**：`scripts/libs/shefu_portrait.py`、`scripts/libs/rules.py`。
- **验收**：`portrait()` 支持传入 地支+天将+八卦+干支 混合信号，输出置信度加权画像。

### P2 —— 语境→维度选择 + 当代映射
- **目标**：问物性/问社会功能/问方位时选不同维度；补当代映射。
- **文件**：`references/现代类象映射.md` → 接入 `portrait()` 维度选择。
- **验收**：`portrait(signals, context=...)` 按语境选维度。

### P3 —— 结构化来意
- **目标**：金口诀占来意歌、大六壬初传课体、梅花体用动爻 → 来意规则函数。
- **文件**：`scripts/libs/rules.py`（新增 `*_laiyi` 函数）。
- **验收**：来意判断从「LLM 即兴」改为「规则函数 + 原文出处」。

### P4 —— 类象库网络化
- **目标**：借鉴 jiulingzi 五行网络建模，用多层字典处理「属性爆炸」，支持当代映射持续补充。
- **文件**：`data/类象库.json` 结构升级 + `shefu_portrait.py` 适配。
- **验收**：类象按 天/地/人 三维编号，支持跨节点关系查询。
