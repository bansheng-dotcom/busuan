# 跃渊八字分析 v1.8 研究版结项报告

> 结项日期：2026-08-17
> 状态：研究版冻结、可交付；不宣称定版准确率。

## 结论

跃渊 v1.8 研究版已完成当前阶段目标：规则冻结、排盘计算与分析分离、标准命例验收、虚构案例审计、女命补充验证、v3 外部诊断封存，以及面向真实用户的安全与不确定度表达。

从现在开始，当前版本不再为了提高测试分数修改命理规则。若未来要改应期或婚恋机制，应另建 v4 未污染验证集。

## 这段时间实际完成了什么

### 1. 把命理分析从“直接给答案”改成研究程序

- 建立 `STRUCTURAL > CORE > SCHOOL > HEURISTIC > SUPPLEMENTAL` 规则层级；
- 建立 S0–S3 输入可信度与 A–E 推理证据分层；
- 固化“先预注册、后读取经历”的后验验证流程；
- 对竞争假设、不确定度、SAFE 红线和流派分歧做显式登记。

### 2. 把计算与推理分开

- 引入 `bazi_engine.py`，用 `lunar-python` 处理四柱、五行、十神、藏干和大运等确定性计算；
- `mingli_rules.py` 与规则约束文件负责可复核的规则资料；
- LLM 负责解释、证据组织和不确定度表达，不负责凭心算排盘。

### 3. 做了多轮、多命例验证

- 标准命例：四柱与起运 **6/6 通过**；
- 虚构案例库：100 例执行审计，记录命中、部分命中和未命中，不把设计命中率冒充真实准确率；
- 女命 v1/v2：用于发现协议、取象与应期问题，诊断化处理；
- v3 外部诊断集：16 例双评、仲裁和证据封存完成。

### 4. 找到了真实短板，而不是用规则补丁掩盖它

- 旺衰、格局、喜用等静态结构判断相对稳定；
- SAFE 边界执行稳定；
- 应期与具体年份约 **50%**，婚恋事件性质、运层吉凶翻转、帮夫/任财分轴仍不稳定；
- dev-3/4/5/6 未达到写入规则的条件，因此没有借后验结果强行升级 v1.9。

## 当前版本能做什么

- 提供结构倾向、证据链、竞争假设和不确定度；
- 给出候选时间窗口、判别年份和用户后验方法；
- 按婚恋、事业、财富、身心等用户问题组织分析；
- 对健康、婚恋和重大事件保持文化解释与安全边界。

## 当前版本不能承诺什么

- 不能承诺具体年份必然发生某件事；
- 不能把结构判断分数解释为产品准确率；
- 不能断夫亡、二婚、绝症、手术等越界结论；
- 不能把 v3 的 85.0% 或 86.2% 对外宣传为总体准确率。

## 结项后的维护规则

1. `SKILL.md` 与 `versions/SKILL_v1.8.md` 继续保持一致；
2. `references/analysis-checklist.md` 只维护 dev-1/dev-2 执行层防错，不改变命理方向；
3. 产品包装、README、样例和 FAQ 可以继续改；
4. 任何命理规则、排盘语义或 SAFE 放宽都必须先立项，建立 v4，再审批 v1.9；
5. 研究重点从“继续涨 holdout 分数”转为“真实用户可读、可验证、知道边界”。

## 最终定位

> **跃渊 v1.8 是一套研究型、允许不确定、用经历验证的八字分析 Skill。**
> 它已经可以作为研究版交付；它不是“最高准确率”的判题程序，也不应被包装成确定性预言工具。
